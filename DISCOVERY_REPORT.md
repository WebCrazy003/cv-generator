# CV Generator — Codebase Discovery Report

_Date: 2026-08-06 · Scope: full working tree · Method: read every source file, extracted real DOCX tokens, ran the test suite._

## 1. What this project is

A **local, single-user CV generator**. A Python stdlib HTTP server serves a React
(CDN, Babel-in-browser) UI. The user pastes CV data as JSON, points at a `.docx`
template, and the backend produces a filled `.docx` plus a `.pdf` in a dated output
folder. No external framework, no database — settings persist to a local
`settings.json`.

### API surface (`app.py`)
- `GET /api/health` → `{status: ok}`
- `GET /api/settings` / `POST /api/settings` → read/write `settings.json`
- `POST /api/generate-cv` → validates, writes DOCX + PDF, returns paths
- `GET /*` → static file serving from `frontend/`

### Generation flow
`build_replacement_map()` → per-`word/*.xml` string `.replace()` → re-zip to DOCX;
separately, `build_simple_pdf()` hand-writes a minimal PDF from plain text lines.

## 3. Ground truth: the real template tokens

Extracted directly from `word/document.xml`:

```
{{summary}}  {{Experience}}  {{company1}}  {{company2}}  {{company3}}  {{Skills}}  {{Education}}
```

Two facts the code does **not** account for:

1. **Tokens are section *markers*, not fill-in fields.** Each token sits immediately
   *before* fully hardcoded sample content (Robson Oliveira's real CV). Example flattened context:
   `...problems.{{Experience}}11/2023 – 07/2026{{company1}}Senior Machine Learning Engineer | SoftXPro...`
   So replacing a token with new text leaves **all of Robson's original content in the output**.
2. **`{{Experience}}`, `{{Skills}}`, `{{Education}}` are split across XML runs.** They only
   appear when tags are stripped; in raw XML the letters live in separate `<w:t>` runs
   (`<w:t>Experience</w:t>` bounded by `{{`/`}}` in neighboring runs). `{{summary}}`,
   `{{company1..3}}` happen to be intact in single runs.

## 4. Confirmed defects (severity-ordered)

### 🔴 P1 — Run-split tokens never match (silent)
`replace_placeholders()` (app.py:115) does a plain `xml_text.replace(token, …)` on raw
Word XML. Because `{{Experience}}`, `{{Skills}}`, `{{Education}}` are fragmented across
runs, **these three tokens are never replaced** and pass through verbatim. This is the
actual "template compatibility" blocker — the plan misdiagnosed it as a missing-map-entry
problem. Fix requires either run-flattening/normalization before replace, or `python-docx`
(already installed, v1.2.0) with paragraph-level joining.

### 🔴 P1 — Marker semantics ignored → duplicated content
Because tokens are markers before hardcoded sample text, output DOCX contains the new
candidate's injected string **plus** the entire original Robson CV. There is no logic to
delete or replace the span *between* markers. The intended design (replace section body,
not just the marker) is unimplemented. **This needs a product decision** (see §6).

### 🟠 P2 — `{{Education}}` has no data path
The template expects `{{Education}}`, but `build_replacement_map()` produces no education
entry and the JSON schema has no `education` field. Token will always remain.

### 🟠 P2 — `{{company2}}`/`{{company3}}` only exist if input has ≥2/≥3 experiences
`company{index}` keys are generated by looping over the input array. The template always
has 3 company slots; a 1-entry input leaves `{{company2}}`/`{{company3}}` unreplaced.
Also, the map sets `{{company1}}` = **companyName only**, but in the template `{{company1}}`
precedes a full role block ("Senior ML Engineer | SoftXPro" + bullets) — semantic mismatch.

### 🟠 P2 — Failing test in repo
`tests/test_template_placeholders.py::test_placeholder_map_contains_expected_tokens`
**fails now**: it asserts `{{company2}}` ∈ map but the payload has only one experience
entry. `1 failed, 1 passed`. The test encodes the (correct) expectation that the map
should be template-driven, not input-count-driven — the code doesn't satisfy it.

### 🟡 P3 — Lower-severity / hardening
- **Path traversal** in static serving: `do_GET` joins `parsed.path` onto `FRONTEND_DIR`
  with no normalization guard (`/../` reachable). Local-only server, but still a defect.
- **Hardcoded `26_` year prefix** in output folder name (app.py:260) — not derived from date.
- **`.pyc`/CDN dependency**: UI depends on unpkg being reachable at runtime; no offline fallback and uses React *development* builds.
- **Unused code**: `build_simple_pdf` computes `escaped_text`/`text` that are never used (app.py:160-161).
- **No content-length cap** on POST body; `escape()` applied to values is correct for XML but company/summary containing `&`/`<` already handled.
- `.claude/settings.local.json` was committed in `c149b85` (should be git-ignored).

## 6. Open product decision (blocks a correct fix)
The template is a *filled sample*, not a blank form. Before implementing, decide the model:
- **(a) Marker-span replacement** — treat each `{{token}}` as the start of a section and
  regenerate everything up to the next token from JSON (deletes Robson's content). Most correct, most work.
- **(b) Blank-template redesign** — strip hardcoded content from the DOCX so tokens sit in
  otherwise-empty sections; then simple replace works (once run-splitting is fixed).
- **(c) python-docx rewrite** — build sections programmatically, ignore most tokens.

## 7. Recommended next steps
1. **Decide §6 model** (product call — recommend (b) blank template + (a) fallback).
2. Fix **run-splitting** (P1) — normalize runs before replace, or move to `python-docx`.
3. Add **education** to schema + map; make company slots **template-driven** (fixed 1..3), fixing the failing test.
4. Add path-traversal guard; derive year in folder name; remove dead code.
5. Add an end-to-end test that generates from `Robson Oliveira_Brazil.docx` and asserts **no `{{...}}` tokens remain** in the output DOCX.
